 Section A – Language Basics & Logic

1. Difference between `let` and `const`
 `const` is used when a variable should not be reassigned after declaration.
`let` is used when the value of a variable may change.
 We avoid `var` because it has function scope and allows redeclaration, which can cause confusion and unexpected errors.

In our program:
```javascript
const eventTitle = "Tech Fest";
let seats = 50;
```

function formatEvent(event) {
    return event.title + " - " +

This function accepts an event object as a parameter and returns a formatted string containing the event title, date and status.

**B. Arrow function with array method (A7)**

```javascript
const availableEvents = events.filter(
    event => event.seats > 0
);
```

The arrow function checks whether an event has more than zero available seats. The `filter()` method returns a new array containing only the events that satisfy this condition.

In our program, it returns Coding Competition and Web Development Workshop.

 Additional explanation – A8: Variable scope

A variable declared inside a function is accessible only within that function (unless it is explicitly made available through another mechanism).

Example:

```javascript
function showMessage() {
    const message = "Welcome to Campus Event Board";
    console.log(message);
}

showMessage();
```

The variable `message` is declared inside `showMessage()`. Therefore, it cannot be directly accessed outside the function. This is called local scope.

Keeping variables in the smallest possible scope makes code easier to understand and reduces unwanted access to variables.

7.Event bubbling
When we click a button, the click event runs on the button first and then “bubbles up” to its parents. Because of this, one listener on #event-list can handle every RSVP button. event.target is the exact element that was clicked, so clicked.classList.contains("rsvp-btn") tells us whether it was an RSVP button.

8.The three fetch states

Loading: while the file is being fetched, the page shows “Loading events...”.
Success: the data is saved in events, the cards are drawn, and the status line shows “Showing 4 of 4 events | 163 seats left”.
Error: if the file is missing, the internet fails or the JSON is broken, the catch block shows “Sorry, we could not load the events right now. Please try again later.” and no cards are shown.

9.Validation and why the server must check again
Built-in attributes: Name required; Email type="email" required; Course required; Year required pattern="[1-4]"; Date of Birth type="date" required.
Custom rule:
if (value.length < 2) {
  nameInput.setCustomValidity("Name must be at least 2 characters long.");
} else {
  nameInput.setCustomValidity("");
}
The server must check again because browser code is in the user’s control. Someone can turn off JavaScript, change the code in DevTools, or send a request directly without using the form. So client-side checks only give quick feedback, and the real protection is the server-side check.
